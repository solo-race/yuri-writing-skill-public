# 百合写作 Skill

用于百合小说、短篇与虚构恋爱日记的创作、续写、修订和叙事分析。重点是具体人物的选择、有限视角、关系冲突、时间结构与语言因果，而不是固定情节套路。

本项目不内置角色、世界观、剧情历史或存档仓库。人物档案均为可选模板；没有系列连续性需求时，无需填写。

## 目录结构

```text
yuri-writing-skill/
├── SKILL.md                        入口：任务选择、写作修订与交付
├── README.md                       中文使用说明
├── style-guide.md                  人物、视角、结构、细节与修订参考
├── character-profile.md            人物档案的人工阅读入口
├── profiles/
│   └── template/
│       ├── index.yaml              按任务加载的路由与正文权威规则
│       ├── profile.yaml            主视角人物的稳定设定模板
│       ├── partner.yaml            另一主要人物的稳定设定模板
│       ├── continuity.yaml         当前持续状态与未结束线索模板
│       └── history.yaml            既往事件与正式篇目索引模板
└── references/
    └── literary-methods.md         可迁移的叙事方法
```

## 使用方式

将完整目录交给支持 Markdown Skill 的助手，入口为 `SKILL.md`。若手动配置本地技能目录，请把文件夹命名为 `yuri-writing-skill`，并保留内部相对路径；发布仓库名可以不同。

可直接说明任务，例如：

- “写一篇两个女性在旅行途中产生分歧的短篇；只使用其中一人的有限视角，不急着和解。”
- “保留这段文字的叙述声音，检查动作因果、重复解释和插叙位置。”
- “根据我提供的人物档案和前两章续写；不要把角色的猜测当成事实。”

普通创作从 `SKILL.md` 开始，遇到具体问题再读取相应参考文件，不必每次加载全部资料。这个 Skill 用于虚构写作，不替代对现实人物或关系的判断。

## 为自己的系列建立档案

1. 将 `profiles/template/` 复制为 `profiles/你的系列名/`。
2. 根据用户提供的设定填写两份人物档案，并在 `index.yaml` 中指定正式正文与索引位置；没有确认的字段保持 `null`、空列表或空映射，不凭空补全。
3. 把仍持续的状态和未结束线索放入 `continuity.yaml`，把需要追溯的旧事放入 `history.yaml`；不要把两者都写成逐日摘要。
4. 将新档案的入口链接加入 `character-profile.md`。需要更多人物时新增档案，并更新该系列的 `index.yaml` 路由。

模板中的注释说明字段用途，不是人物设定。正文与摘要冲突时回查正式正文；用户要求修改既定设定时，明确这是修订而非偷偷补写历史。归档或更新远端内容仍须按用户授权执行。

## 叙事方法与边界

`style-guide.md` 提供日常写作与修订判断，`references/literary-methods.md` 保留独立可用的抽象技法，不含特定作品的学习来源或对应表。使用方法不等于移植别人的人物、情节与标志性事件；若用户另外要求分析具体作品，应以当次可核验的文本为依据。
